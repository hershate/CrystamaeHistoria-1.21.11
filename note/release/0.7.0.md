## 设计模式沉淀（新增，与 0.6.0 模式清单并列）

26. **成员资格纪元与计数纪元分离**：同一数据源的"值变化"与"成员
    变化"分别失效各自的缓存——高频计数写（每次施法）不再无谓失效
    低频成员缓存（解锁）。
27. **（过程）批量文本替换后必须核对同名字段 check/set 配对**：
    round-31 半应用缺陷由服务器断言暴露（两族缓存永久 miss）——
    同构代码族的字段级重构应逐方法核对而非全局替换。

## 过程治理记录

- 基准设施三项慢宿主加固（round-31）：configParse 组批量 20→4、
  测试服 `spigot.yml timeout-time` 60→600、会话窗口 660→1200s
  （宿主 ~2x 变慢时整套基准超窗 + 重型组整组单 tick 触发 watchdog
  强制停机的完整排查记录见 round-31.md）。

## 兼容性

- 无数据格式变更；集合为进程内读缓存（重启重建）；
- 解锁判定即时性不变（解锁写后下一次查询即见新值）；
- per-call `hasUnlocked*` 与全部对外 API 保留；
- `depend`/`softdepend` 与 0.6.0 一致。
