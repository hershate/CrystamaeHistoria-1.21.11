## 兼容性设计（四组双读）

- **故事列表**：v2 键优先、v1 键回退；写路径触碰即迁移（v1 键移除）；
- **故事上限**：int 键优先、JSON 回退；旧编码物品永久可读；
- **法杖/区块**：**同键双读**（v2 TAG_CONTAINER 与 v1 数组共用键，
  类型不匹配经断路器转 null 回退）；写 v2 即覆盖；
- crafted/损坏数据降级语义与 v1 逐条目跳过同级（限次告警）；
- 降级到旧版本插件无法读 v2 数据（从未承诺的方向性，特此注明）；
- 对外插件 API 零变更。

## 设计模式沉淀（新增，与 0.5.0 模式清单并列）

21. **扁平数组编码**：N 个同构子容器 → 单容器平行数组
    （连接串/int[]/long[]/打包串），PDC 键操作 O(N) → O(1)。
22. **同键双读**：不同原语类型（容器 vs 数组）共用一个键，
    类型不匹配经断路器转 null 后回退旧编码——无需第二键、无残留迁移。
23. **消费面先行核验**：编码扁平化前核验全部读方（round-27 发现
    tier 只写不读，编码 2 数字 → 1；round-29 发现区块内世界必然
    共享，逐条目世界键 → 单键）。
24. **（红线）裸 PDC 调用必须自防御**：Paper 对类型不匹配抛裸 IAE，
    未经 DataTypeMethods 断路器的裸调用会在旧编码值上炸穿调用链
    （round-28 服务器测试拦截，fix da0d919）。
25. **无捕获读取路径不容异常**：区块加载期的降级设计为空列表 +
    限次告警而非抛出（round-29 预防性应用 round-28 教训）。
